## 4. 关键业务证据

### 4.1 婚姻进程与首页复盘

- 8 个节点独立存在；男方上门、父母见面和领证已有事实记录，女方上门仍保持未完成，订婚保持“已跳过”，婚礼保持独立未完成。
- 首页显示主线进度 `4 / 8`、两次上门 `1 / 2`、领证实际日期 `2026.08.14` 和婚礼 `2026.08.30`，并显示“仪式节点独立记录”。
- 首页复盘文案显示“你已经提前记录了后续事实，系统保留实际发生顺序；未完成节点仍可单独安排”，未把推荐顺序包装成法律或家庭审批结论。
- `GET /api/wedding/process/nodes` 返回 HTTP 200；婚礼节点 `plannedDate=2026-08-30`、`status=not_started`，领证节点仍有独立的 `plannedDate=2026-08-20` 和实际日期。

### 4.2 阶段行动项与花费联动

- 真实页面创建阶段行动项“EGO-20260814-JJJ 预约民政局领证”，默认阶段为依法办理结婚登记、负责人为双方；切换为进行中后页面显示在执行看板。
- 新增花费“EGO-20260814-JJJ 领证预约费用”，类别为场地、支付状态为已支付、计划/实际金额均为 `200`，并关联上述行动项。
- `GET /api/wedding/expenses` 和 `GET /api/wedding/tasks` 均返回 HTTP 200；创建时花费 `taskId` 指向行动项，删除行动项确认后花费保留且页面显示“未关联任务”，同源回读确认 `taskId=null`。
- 随后删除测试花费；最终 `GET /api/wedding/expenses` 与 `GET /api/wedding/tasks` 均返回空数据，概览实际花费回到 `¥0.00`。

### 4.3 预算、婚期与婚礼节点同步

- 页面设置预算 `120000`、婚礼日期 `2026-08-30`，显示成功提示“备婚预算已更新”。
- `GET /api/wedding/budget` 返回 HTTP 200，业务结果为 `totalBudget=120000`、`weddingDate=2026-08-30`。
- `GET /api/wedding/overview` 返回 HTTP 200，业务结果为 `remainingBudget=120000`、`budgetUsedPercentage=0`、`daysUntilWedding=16`。
- 执行页、首页概览、时间线和婚礼节点均显示同一婚礼日期；领证日期没有被预算婚期覆盖。
