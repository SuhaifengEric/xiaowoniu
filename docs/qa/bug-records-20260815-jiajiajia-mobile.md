# 嫁嫁嫁移动端体验专项 BUG 记录（2026-08-15）

## BUG-20260815-MOB-001：短屏首屏看不到婚姻进程主操作（已修复，回归通过）

| 项目 | 内容 |
| --- | --- |
| 页面/用例 | `/wedding`；JJM-001、JJM-002、JJM-003 |
| 优先级 | P1（核心任务可完成，但必须先穿过大量非主线内容并继续滚动） |
| 环境 | 本地最新 `main`；Ego Browser；空婚姻进程用户 |
| 复现步骤 | 分别以 `320×568`、`400×439`、`390×844` 打开页面，记录工具栏、tab、婚姻进程卡和固定底栏边界 |
| 初始证据 | `320×568`：进程卡 `y=538`，底栏 `y=491`，首屏可见进程高度为 `0`；`400×439` 滚动到与用户截图一致的位置后，进程卡 `y=297`，底栏 `y=362`，主按钮 `y=496..540`；`390×844`：工具栏高 `358px`，进程卡从 `y=512` 开始，主按钮下缘进入底栏区域 |
| 根因 | 手机仍使用桌面信息顺序；页面导航、长说明和三排执行操作全部位于核心婚姻进程之前 |
| 预期 | 四档手机视口内，婚姻进程标题和主操作优先且不被底栏覆盖 |
| 修复 | 压缩手机头部，把行动/花费/预算移入“执行”，缩短短屏说明与间距，并给页面保留固定底栏安全区 |
| 回归证据 | 主按钮/底栏起点：`320×568` 为 `y=237..281 / 503`；`400×439` 为 `213..257 / 374`；`390×844` 为 `358..402 / 779`；`844×390` 为 `213..257 / 325` |
| 状态 | 已修复，Ego Browser 回归通过 |

## BUG-20260815-MOB-002：五项本地视图标签在手机端全部被截断（已修复，回归通过）

| 项目 | 内容 |
| --- | --- |
| 页面/用例 | `/wedding` 五项视图；JJM-005 |
| 优先级 | P1（用户无法仅凭文字稳定识别五个核心视图） |
| 环境 | 本地最新 `main`；Ego Browser；`320×568`、`400×439` |
| 初始证据 | `320px` 下每个标签文字 `clientWidth=6`、`scrollWidth=56`；`400px` 下 `clientWidth=22`、`scrollWidth=56`，五项均 `clipped=true` |
| 根因 | tab 按钮允许 `flex-shrink` 且使用 `min-w-0`，内部标签同时使用 `truncate`；容器虽声明横向滚动，子项却先被压缩 |
| 预期 | 手机显示完整短标签，完整业务名称继续作为可访问名称；不依赖省略号或记忆图标 |
| 修复 | 手机改为五等分网格，显示“进程、阶段、共识、执行、设置”；完整名称保留为 `aria-label` |
| 回归证据 | `320px` 下五项均约 `57.6×44px`，可见短标签无裁切；角色树仍读取“婚姻进程、阶段记录、双方共识、婚礼执行、流程设置” |
| 状态 | 已修复，自动化与 Ego Browser 回归通过 |

## BUG-20260815-MOB-003：执行操作在移动端压过真实婚姻主线（已修复，回归通过）

| 项目 | 内容 |
| --- | --- |
| 页面/用例 | `/wedding` 页面头部和婚礼执行视图；JJM-006 |
| 优先级 | P1（操作层级与已确认的产品主线相反） |
| 初始现象 | “新增行动项、增花费、设置预算”以三排全宽按钮占据手机首屏；“当前婚姻阶段、下一步、建立进程”位于其后 |
| 产品边界 | 婚姻阶段、当前节点、下一步行动和双方共识属于主线；任务、花费和预算属于婚礼执行支撑 |

| 修复 | 手机头部移除三排执行按钮；“执行”视图增加三列快捷操作，并把概览压缩为两列关键数据 |
| 回归证据 | `320px` 下“新增行动、记花费、预算”均约 `91×56px`；首次进入进程视图时不再出现这三项操作 |
| 状态 | 已修复，自动化与 Ego Browser 回归通过 |

## BUG-20260815-MOB-004：手机横屏误用高占用桌面头部（已修复，回归通过）

| 项目 | 内容 |
| --- | --- |
| 页面/用例 | `/wedding`；JJM-004 |
| 优先级 | P1（横屏短高度下主内容仍落在首屏之外） |
| 环境 | Ego Browser `844×390` |
| 初始证据 | 页面在 `768px` 宽度断点后隐藏底部主导航并切换桌面头部；工具栏到 `y=271`，本地 tab 到 `y=324`，进程卡从 `y=344` 开始，主按钮位于 `y=520..564`，完全不在首屏 |
| 根因 | 只按宽度判断桌面/手机，未结合横屏短高度这一使用情境 |
| 预期 | 手机横屏启用紧凑头部、短标签和底部主导航；核心主操作在首屏可见 |
| 修复 | 为 `768–1023px` 且短高度的横屏增加移动工作台断点，沿用紧凑头部、短标签和底部导航 |
| 回归证据 | `844×390` 下主按钮 `y=213..257`，底栏从 `y=325` 开始；`scrollWidth=clientWidth=844` |
| 状态 | 已修复，Ego Browser 回归通过 |

## BUG-20260815-MOB-005：日期选择器在窄屏和短屏被裁切（已修复，回归通过）

| 项目 | 内容 |
| --- | --- |
| 页面/用例 | 行动项日期选择器及所有复用 `DatePicker` 的表单；JJM-012、JJM-016 |
| 优先级 | P1（最右列日期或下半月日期不可稳定点击） |
| 环境 | Ego Browser；`320×568`、`400×439`、`844×390` |
| 初始证据 | `320×568` 下浮层为 `x=32..320`，日历网格却为 `x=45..353`，向右超出 `33px`；`400×439` 下表单滚动到日期字段后，浮层为 `y=249..615`，超出视口底部 `176px` |
| 根因 | 七列日历固定使用 `44px` 列宽，但窄屏浮层仍保留 `32px` 外边距和 `24px` 内边距；Radix 在上下空间都不足时保持锚点方向，没有把高 `367px` 的日历移回短视口 |
| 修复 | `≤365px` 使用全宽紧凑浮层；移动/平板短视口（宽 `≤1023px` 且高 `≤700px`）把日期浮层居中并限制最大高度；去除日期单元默认内边距，使日期与清除按钮都达到 `44×44px` |
| 回归证据 | `320×568` 日历完整位于 `x=5..315`，日期按钮和清除按钮均为 `44×44px`，页面无横向溢出；`400×439` 浮层为 `x=24..376 / y=36..403`；`844×390` 为 `x=246..598 / y=12..378` |
| 状态 | 已修复，自动化、构建与 Ego Browser 回归通过 |

## BUG-20260815-MOB-006：空婚姻进程下阶段与共识 Tab 展示同一空态（已修复，回归通过）

| 项目 | 内容 |
| --- | --- |
| 页面/用例 | `/wedding`；JJM-003、JJM-017 |
| 优先级 | P1（用户无法判断当前 Tab 的业务范围，也无法理解阶段和共识各自会记录什么） |
| 环境 | 本地开发服务；Ego Browser；`390×844`；`process === null` |
| 初始证据 | 切换“阶段记录”和“双方共识”后，两个面板都显示“先把你们正在经历的阶段记下来”，与“婚姻进程”空态完全相同；页面实际切换了 Tab，但内容没有体现视图差异 |
| 根因 | `Wedding/index.tsx` 在 `process === null` 时让“阶段”和“共识”都复用默认 `MarriageProcessCard` 空态，没有传递当前视图语义 |
| 预期 | 三个 Tab 即使在空状态也应分别说明自己的记录目标，并保留建立婚姻进程入口；选中态、面板关联和页面宽度保持正常 |
| 修复 | 为 `MarriageProcessCard` 增加 `emptyView` 变体；阶段传入 `stages`，共识传入 `agreements`，并分别提供“从第一个阶段开始记录”“把重要共识留在这里”的引导文案；补充页面自动化断言 |
| 回归证据 | `wedding-page.test.tsx` 专项 18/18 通过；Ego Browser `390×844` 下三项分别显示“先把你们正在经历的阶段记下来”“从第一个阶段开始记录”“把重要共识留在这里”，三项均 `aria-selected=true` 且 `scrollWidth=clientWidth=390` |
| 状态 | 已修复，自动化、lint、构建、差异检查与 Ego Browser 回归通过 |
