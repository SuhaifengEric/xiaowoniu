# 嫁嫁嫁移动端体验专项测试用例（2026-08-15）

## 1. 目标与范围

本轮把“嫁嫁嫁”移动端入口从桌面页面的缩小版，调整为以当前婚姻阶段和下一步行动为核心的个人工作台。专项验收覆盖：

- `320×568` 小屏手机竖屏；
- `400×439` 短屏视口（复现用户截图）；
- `390×844` 常见手机竖屏；
- `844×390` 手机横屏；
- `768×1024` 平板和 `1280×800` 桌面回归；
- 空婚姻进程、已有婚姻进程、阶段记录、双方共识、婚礼执行和流程设置；
- 页面首屏、五项视图导航、底部主导航、长列表、长文本和 Dialog。

本轮只形成本地自动化、Ego Browser 和页面状态证据，不代表真实 iPhone/Android、Staging 或生产验收。

## 2. 证据与通过规则

| 项目 | 约定 |
| --- | --- |
| 页面 | `http://localhost:5173/wedding`，使用查询串避免复用旧 Vite 页面 |
| 浏览器 | Ego Browser 独立 task space；不输出 Token、Cookie 或密码 |
| 自动化 | Wedding 页面/组件测试、frontend lint、frontend build、`git diff --check` |
| 横向布局 | `document.documentElement.scrollWidth === clientWidth` |
| 底栏遮挡 | 首屏核心标题和主操作的边界不得进入 `.mobile-tabbar`；滚动到底后最后一个操作仍可完整聚焦和点击 |
| 本地视图导航 | 五项均有完整可访问名称；可见短标签不出现省略号或裁切；单项触控高度不小于 `44px` |
| 页面主任务 | “婚姻进程/当前阶段/下一步”先于行动项、花费和预算；执行操作在“婚礼执行”视图内集中提供 |
| 失败纪律 | 可复现问题先写入 `bug-records-20260815-jiajiajia-mobile.md`；修复后再回归，不把未执行项写成通过 |
