| 项目 | 内容 |
| --- | --- |
| 发现时间 | 2026-08-14 |
| 页面/用例 | `/wedding` 阶段记录/婚礼执行；阶段行动项创建 |
| 优先级 | P1（核心业务写入结果不可见） |
| 环境 | 本地前端 `http://localhost:5173`、本地后端 `http://localhost:3000`、Ego Browser 任务空间 87、合成 QA 用户 |
| 复现数据 | 名称“预约民政局领证”；阶段“依法办理结婚登记”；负责人“双方”；完成标准“双方确认日期并完成预约”；类别“场地” |
| 复现步骤 | 打开阶段行动项表单，填写必填内容，点击“保存任务”；弹窗关闭后进入执行页查看行动项 |
| 初始现象 | 首次操作后弹窗关闭；执行页仍显示“还没有备婚任务”。使用当前页面认证状态同源回读 `GET /api/wedding/tasks?limit=50&offset=0`，返回 HTTP 200 且数据为空。 |

| 复测结果 | 重新打开同一表单并使用真实页面点击完成填写和保存：`POST /api/wedding/tasks` 返回 HTTP 200；随后刷新 `GET /api/wedding/tasks?limit=50&offset=0` 返回 HTTP 200 且包含新任务；执行页刷新后显示任务看板和任务进度 `1`。 |
| 证据边界 | 初始现象曾出现，但未能在受控真实点击链路中稳定复现；未发现可确认的代码缺陷，因此不进行代码修复。 |
| 状态 | 未复现，关闭 |

本轮已检查浏览器请求、前端提交数据、后端写入和刷新链路；受控复测完成后关闭本条记录。

## BUG-20260814-002：嫁嫁嫁视图方向键切换后焦点未随选中项移动（已确认，待修复）

| 项目 | 内容 |
| --- | --- |
| 发现时间 | 2026-08-14 |
| 页面/用例 | `/wedding` 嫁嫁嫁五项视图；JJJ-027 |
| 优先级 | P1（键盘用户无法连续浏览核心视图） |
| 环境 | 本地前端 `http://localhost:5173`、本地后端 `http://localhost:3000`、Ego Browser 任务空间 89、合成 QA 用户 |
| 复现步骤 | 1. 打开 `/wedding`，确认“婚姻进程”标签处于选中状态；2. 将焦点放到“婚姻进程”标签；3. 按一次 `ArrowRight`；4. 继续按 `ArrowRight`，尝试依次进入“双方共识”“婚礼执行”“流程设置”。 |
| 初始现象 | 第一次按键后 `aria-selected="true"` 已切换到“阶段记录”，内容面板也随之切换，但浏览器焦点仍停留在“婚姻进程”按钮；后续每次 `ArrowRight` 都继续按原按钮索引计算，选中状态停留在“阶段记录”，无法继续浏览后续标签。 |
| 预期结果 | 方向键切换标签后，焦点应移动到新的选中标签；连续按右键应按“婚姻进程 → 阶段记录 → 双方共识 → 婚礼执行 → 流程设置”顺序切换，按左键反向切换。 |
| 复测结果 | 在同一真实浏览器页面重复执行：初始焦点为“婚姻进程”；一次右键后选中项为“阶段记录”、焦点文本仍为“婚姻进程”；再连续五次右键后选中项仍为“阶段记录”。问题稳定复现。 |
| 证据 | Ego 页面可见 `role=tab` 的 `aria-selected` 与实际焦点不一致；浏览器事件链可稳定复现。 |
| 状态 | 已确认，待修复 |

本条仅记录问题，不在本轮测试中直接修改产品代码；后续修复需补充键盘焦点回归。

## BUG-20260814-003：预算弹窗通过 Escape 关闭后焦点未恢复到触发按钮（已确认，待修复）

| 项目 | 内容 |
| --- | --- |
| 发现时间 | 2026-08-14 |
| 页面/用例 | `/wedding` 预算与婚期弹窗；JJJ-029 |
| 优先级 | P1（键盘用户关闭弹窗后失去焦点上下文） |
| 环境 | 本地前端 `http://localhost:5173`、本地后端 `http://localhost:3000`、Ego Browser 任务空间 89、合成 QA 用户 |
| 复现步骤 | 1. 在婚姻进程首页点击“调整预算与婚期”；2. 确认弹窗打开并将焦点置于预算输入框；3. 按 `Escape` 关闭弹窗；4. 读取当前活动元素。 |
| 初始现象 | 弹窗关闭且页面内容保留，但活动元素变为 `BODY`，没有回到“调整预算与婚期”触发按钮。 |
| 预期结果 | 通过 Escape、取消或关闭按钮退出 Dialog 后，焦点应恢复到打开该 Dialog 的触发按钮，便于键盘用户继续操作。 |
| 复测结果 | 在同一真实浏览器页面重复执行：打开后活动元素为 `#wedding-budget-total`；Escape 后 `role=dialog` 数量为 `0`，活动元素为 `BODY`。问题稳定复现。 |
| 证据 | Ego 页面关闭状态可见；页面 DOM 活动元素读取结果为 `BODY`，不是“调整预算与婚期”按钮。 |
| 状态 | 已确认，待修复 |

本条仅记录问题，不在本轮测试中直接修改产品代码；后续修复需覆盖 Escape、取消按钮和关闭按钮三条退出路径。
