## BUG-20260812-001 登录失败未展示错误且清空输入

| 项目 | 内容 |
| --- | --- |
| 严重程度 | P0 |
| 来源 | 本地真实浏览器（Ego Browser） |
| 用例 | AUTH-005 |
| 页面/视口 | `/login`；1470×836 |
| 测试账号 | 合成登录页输入；不存在的邮箱 `wrong@example.com`，密码为一次性错误值（不在文档中记录） |
| 前置条件 | 已退出登录，打开登录页 |
| 复现次数 | 1/1 |
| 证据 | Ego Browser 页面状态：URL 仍为 `/login`；页面未出现“登录失败”或 `role=alert` 文案；邮箱和密码输入值均为空且控件恢复可编辑 |

### 复现步骤

1. 打开 `/login`。
2. 输入格式合法但不存在的邮箱。
3. 输入错误密码并点击“登录”。
4. 等待请求完成，观察页面和输入框。

### 预期结果

显示可理解的登录失败错误；邮箱和密码输入保留，按钮恢复可用；不跳转 Dashboard。

### 实际结果

仍停留在 `/login`，但没有显示失败错误；邮箱和密码输入均被清空。

### 根因

`frontend/src/services/api.ts` 的响应拦截器把所有 `401` 都当成当前会话失效。登录接口本身在凭证错误时也返回 `401`，于是拦截器清理本地登录态并重新加载 `/login`，登录页的输入状态和 `auth.store` 中刚设置的错误一起丢失。

### 修复与复测

- 仅对非登录/注册接口的 `401` 执行全局清理和跳转；`/api/auth/login`、`/api/auth/register` 的 `401` 保留给表单错误处理。
- 登录页和注册页的错误区域增加 `role="alert"`。
- Ego Browser：输入错误凭证后仍停留 `/login`，显示“邮箱或密码错误”，邮箱和密码值保留，按钮恢复可用；未因登录 `401` 误清理已有会话。
- 自动化回归：`api.test.ts`、`login-page.test.tsx`、`auth.store.test.ts` 通过。

### 状态

已修复，2026-08-13 Ego Browser 回归通过。

## BUG-20260812-003 Wedding 删除任务失败并显示 Network Error

| 项目 | 内容 |
| --- | --- |
| 严重程度 | P1 |
| 来源 | 本地真实浏览器（Ego Browser） |
| 用例 | WED-018、WED-019 |
| 页面/视口 | `/wedding`；1280×1900 |
| 测试账号 | 合成测试账号；不记录密码、Token 或 Cookie |
| 前置条件 | 已登录；看板中存在 `Ego 临时备婚任务`；后端 `/health` 与 `/readyz` 均返回成功 |
| 复现次数 | 1/1（服务恢复后重试） |
| 证据 | 点击确认删除后，页面显示 `Network Error`；删除确认框关闭或保持错误状态，任务仍在“待办”列；服务端健康检查在重试前已确认正常 |

### 复现步骤

1. 打开 `/wedding`，在“任务看板”找到 `Ego 临时备婚任务`。
2. 点击该任务的“删除”按钮。
3. 在“确认删除备婚任务”弹窗点击“确认删除”。
4. 等待请求完成，观察错误提示和任务看板。

### 预期结果

显示删除成功，任务从看板和概览计数中移除；关联花费按提示保留并解除关联。

### 实际结果

页面显示 `Network Error`，任务仍保留在待办列，删除未完成。确认框在首次尝试时保持打开；服务恢复后重试时确认框关闭但错误仍出现。

### 根因

后端 `deleteTask` 的用户隔离删除实现和 `DELETE /api/wedding/tasks/:id` 契约均正确，真实 HTTP/服务测试没有发现删除服务根因。页面阻断来自共享弹层交互层：关闭状态的 Select/Popover 退出动画在 Ego 中未可靠触发 `animationend`，残留的 Radix 层继续占用交互锁；同时 Dialog 的打开动画使用 `transform` 覆盖了居中定位，使确认按钮可能落到视口外，删除确认点击不可靠。

### 修复与复测

- Select、Popover 关闭时取消退出动画，使 Radix Presence 立即卸载关闭层。
- Dialog 去掉会覆盖 `translate(-50%, -50%)` 的变换动画，保持弹窗稳定居中。
- Ego Browser：创建一条新任务并关联一条花费，确认删除任务后任务从看板消失；花费保留并变为“未关联任务”，页面显示“备婚任务已删除”，无 `Network Error`，无残留锁。
- 自动化回归：Wedding store、service、route 以及成功/失败删除页面用例通过。

### 状态

已修复，2026-08-13 Ego Browser 回归通过。

## BUG-20260812-002 Wedding 日期选择后弹窗其余控件不可交互

| 项目 | 内容 |
| --- | --- |
| 严重程度 | P1 |
| 来源 | 本地真实浏览器（Ego Browser） |
| 用例 | WED-025、WED-026（同时影响使用日期选择器的 Wedding 花费主流程） |
| 页面/视口 | `/wedding`；1280×1900 |
| 测试账号 | 合成测试账号；不记录密码、Token 或 Cookie |
| 前置条件 | 已登录；已有一条临时备婚任务；Wedding 预算与婚期已设置 |
| 复现次数 | 1/1（刷新页面后重新复现） |
| 证据 | Ego Browser 截图：`/var/folders/0v/b30bgwpx6m528khblwmsqxsh0000gn/T/ego-browser-shot-54034-1.png`；页面可见“新增备婚花费”弹窗，日期已选为 2026年8月15日，但类别、支付状态等控件点击后不展开；浏览器状态显示 `body` 的 `pointer-events` 为 `none` |

### 复现步骤

1. 打开 `/wedding`，点击“新增花费”。
2. 在“花费日期”中打开日期选择器，选择可见日期（本次为 2026年8月15日）。
3. 回到“新增备婚花费”弹窗，点击“花费类别”或“支付状态”。

### 预期结果

日期选择器关闭后，弹窗仍保持可操作；类别、支付状态、关联任务、金额和保存按钮均可继续操作。

### 实际结果

日期文字已更新，但弹窗后续控件无法展开或响应；页面仍处于不可交互状态，无法完成新增花费保存。

### 根因

日期选择器使用 Popover。Popover 关闭时的 `data-state=closed` 退出动画依赖浏览器触发 `animationend`；在 Ego 中关闭节点未及时卸载，Radix 的 `DismissableLayer` 锁仍残留，导致外层花费弹窗后续控件无法可靠交互。

### 修复与复测

- 移除 Popover 和 Select 的关闭退出动画，保留打开时的视觉效果并让关闭层立即卸载。
- Ego Browser：选择 `2026年8月16日` 后，日历从 DOM 消失；类别、支付状态、关联任务、金额均可继续填写并保存，花费明细成功回读。
- 选择外层弹窗中的控件期间只保留外层 Dialog 的正常锁；保存后弹窗关闭，`pointer-events` 和滚动锁均清零。
- 自动化回归：DatePicker、Wedding dialog 和 Wedding page 测试通过。

### 状态

已修复，2026-08-13 Ego Browser 回归通过。

## BUG-20260812-004 Wedding 新建任务类别选择器阻断弹窗操作

| 项目 | 内容 |
| --- | --- |
| 严重程度 | P1 |
| 来源 | 本地真实浏览器（Ego Browser） |
| 用例 | WED-011、WED-014 |
| 页面/视口 | `/wedding`；1280×1900 |
| 测试账号 | 合成测试账号；不记录密码、Token 或 Cookie |
| 前置条件 | 已登录；Wedding 页面正常加载；任务看板为空 |
| 复现次数 | 1/1（刷新页面后干净复现） |
| 证据 | 点击“任务类别”后，页面状态为 `body` `pointer-events: none`、`data-scroll-locked=2`；类别选择层关闭状态残留，Ego 无法选择“其他”等选项，保存按钮无法继续完成任务创建 |

### 复现步骤

1. 打开 `/wedding`，点击“新建任务”。
2. 输入合法任务名称。
3. 点击“任务类别”下拉框。
4. 尝试选择任一类别并保存。

### 预期结果

类别下拉框正常展开并可选择；选择完成后弹窗其余字段和“保存任务”按钮仍可操作。

### 实际结果

点击类别后页面进入不可交互状态，类别选项无法完成选择，保存流程被阻断；本次未创建任务数据。

### 根因

任务类别使用共享 Select。Select 关闭退出动画未可靠卸载时，会将已关闭的选择层和外层 Dialog 的锁叠加，导致类别选择后的表单不能继续操作。另有共享 Dialog 打开动画覆盖居中 `transform`，使长表单底部的保存按钮可能离开视口。

### 修复与复测

- Select 关闭时立即卸载，不再等待不可靠的退出动画。
- Dialog 去掉覆盖定位的变换动画，长表单保持居中且保存按钮可见。
- Ego Browser：新建任务时类别、计划日期、状态、优先级均可连续选择，点击保存后任务进入看板；弹窗关闭后无残留 `listbox`，`pointer-events` 和滚动锁均清零。
- 自动化回归：Wedding dialog、Wedding page 和弹层相关测试通过。

### 状态

已修复，2026-08-13 Ego Browser 回归通过。
